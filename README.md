# 加油站班次交接批次

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia（纯前端演示，数据保存在浏览器 localStorage）
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 逻辑测试：`npm test`（合并引擎 23 项 + 端到端 17 项）

## 解决的问题

旧版只有一条本地交接记录：断网时两名值班员各自录入，恢复后同一笔支付被重复计算；
站长复核后金额还能被改动。现扩展为**交接批次**模型。

## 数据模型

- **批次 Batch**：一个班次（营业日期 + 早/中/晚班）关联该班次的油枪读数、现金流水、电子支付流水。
- **流水 Flow**：身份 = `来源终端编号 + 终端内自增流水号`（如 `T01:7`），全局唯一。
- **服务端态**（`dfwlfront-7-server-v2`）：合并后的权威批次/流水。
- **终端本地态**（`dfwlfront-7-local-T01` 等）：每个终端独立保存待同步批次与流水 outbox，断网可继续录入。

## 合并与并发规则

1. **重连按终端编号 + 流水号 upsert 合并**，同一流水只算一次；同终端断网期间重试补传不会产生第二条。
2. **同凭证号重复支付检测**：两名值班员录了同一笔（同凭证号）现金/电子支付时，两笔都挂起为「疑似重复」、暂不计金额，由站长选择保留哪一笔（另一笔作废）。
3. **字段级三向合并**：以同步基线版本（snapshot）为共同祖先——
   - 只有一方改过：采用改动值；
   - 双方改成相同值：收敛；
   - **双方都改且不同：保留两版（后到/在先）进入字段冲突，绝不以后到覆盖**，站长逐字段裁决。
4. **复核冻结**：站长复核后批次与全部关联流水冻结，任何终端不能再改金额；复核前要求冲突/重复全部处理、待同步流水全部完成。
5. **迟到流水**：冻结后才同步上来、原归属该批次的流水自动归入下一班次（开放批次，没有则自动新建），
   原批次结算差额标记**失效**（页面加删除线），下一批次 `承接差额 = 原批次差额 + 迟到流水金额` 重算。
6. **写入失败保留**：同步逐项执行（先批次后流水），可开启「模拟网络故障」随机中断；
   已完成项出队、未完成项保留在 outbox，重试只补未完成批次与流水。

## 页面说明

- 顶部控制条：切换 T01/T02/T03 终端（同一浏览器模拟三台设备，数据互不覆盖）、网络开关、故障注入、手动同步。
- 指标卡：开放批次、已冻结批次、各终端待同步总数、待站长处理（冲突 + 重复）数。
- 「各终端同步状态」表：逐终端显示待同步批次/流水数量与最近成功同步时间。
- 批次卡片：泵码销量、现金/电子应收与实收、承接差额、结算差额（失效后删除线展示）、
  流水列表（含冲突裁决、重复处理、修改弹层）、站长复核弹窗（预填实收并实时预览差额）。
- 底部「升级前的两条示例记录」：旧 localStorage 数据首次打开时一次性迁移为 `legacy` 批次（含对应三笔流水），
  仍可查看原数值，不参与新结算链；旧的待复核记录可做存档式复核。

## 关键文件

- `src/types.ts` 数据结构
- `src/server.ts` 合并引擎（三向合并、凭证去重、冻结、结算链）
- `src/storage.ts` localStorage 持久化与旧记录升级
- `src/store.ts` Pinia：终端 outbox、逐项同步、视图合成
- `src/components/*` 批次卡片、流水行、录入表单、终端面板
- `src/__test__/*` 合并引擎与端到端场景测试
